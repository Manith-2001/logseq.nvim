1. INTRO                                                *logseq-intro*

logseq.nvim handles Logseq *file-graph* notes directly from Neovim:
find/open pages, follow |[[links]]| under the cursor, open today's
journal, and create new pages — all with Logseq's dangling-ref
semantics (following a missing page opens an empty buffer; no file is
created until you add content and write).

Scope (v0.1): file graphs only (`pages/*.md`, `journals/*.md`).
Logseq DB graphs (`*.sqlite`), block refs, and queries are out of
scope. TODO lists are read-only except single-line state cycling
(|:LogseqCycleTodo|, one line at a time — no multi-line cycling, no
timestamps/LOGBOOK). See README.md for the milestone plan.

==============================================================================
2. REQUIREMENTS                                  *logseq-requirements*

- Neovim 0.12+ (uses |vim.pack|, |vim.fs.dir|, `vim.ui.input`)
- Optional: telescope.nvim (a |vim.ui.select| fallback is used otherwise)
- A Logseq file graph, e.g. `~/dev/notes_logseq/` with `pages/` +
  `journals/` subdirectories (or `logseq/config.edn`)

==============================================================================
3. SETUP                                                *logseq-setup*

With |vim.pack| (no plugin manager needed): >lua
    vim.pack.add({ { src = 'https://github.com/Manith-2001/logseq.nvim' } })

    -- Tell the plugin where your graph lives (or open a file inside
    -- the graph and let it auto-detect):
    vim.g.logseq = { graph_path = '~/dev/notes_logseq' }
<
No |logseq-setup| function call is required. `setup()` exists only to
merge options from Lua: >lua
    require('logseq').setup({ graph_path = '~/dev/notes_logseq' })
<
Precedence, low to high: defaults < `vim.g.logseq` < `setup(opts)`.

After install, run `:helptags ALL` once so this help is indexed, then
|:checkhealth| `logseq` to verify the graph resolves.

==============================================================================
4. USAGE                                                *logseq-usage*

- `:LogseqFind` ......... pick a page or journal, open it.
- `:LogseqFollow` ....... open the |[[link]]| under the cursor.
- `:LogseqToday` ........ open today's journal page.
- `:LogseqNew [title]` .. open a page; prompts when no title is given.
- `:LogseqGraphs` ....... pick the active graph (see
  |logseq-multigraph|).
- `:LogseqGraph [title]`  explore a page's links (Linked + Backlinks)
  in a scratch buffer (see |logseq-graphview|).
- `:LogseqTodos` .......... pick a `- TODO` task and jump to its line.
- `:LogseqTodosView` ...... see all tasks grouped by file in a scratch
  buffer (see |logseq-todos|).
- `:LogseqCycleTodo` ...... cycle the `- MARKER` on the cursor line to
  its next state (see |logseq-todos|).
- `:LogseqSmartAction` .... follow the link, else cycle the task, else
  move down (see |logseq-smartaction|).
- `:LogseqNextLink` / `:LogseqPrevLink` jump to the next / previous
  link (see |logseq-smartaction|).

Markdown buffers inside a graph get buffer-local treatment only
(`b:logseq_root` is set, hard tabs are kept literal for Logseq-style
block nesting, `<CR>` / `[o` / `]o` run the smart action and link
navigation). Nothing global is changed; pre-existing maps are never
clobbered (see |logseq-mappings|).

==============================================================================
5. COMMANDS                                          *logseq-commands*

                                                            *:LogseqFind*
:LogseqFind
    List `pages/*.md` + `journals/*.md` via Telescope
    (|vim.ui.select| fallback) and edit the choice.

                                                          *:LogseqFollow*
:LogseqFollow
    Follow the `[[page]]`, `#[[page with spaces]]`, or `#tag` under
    the cursor. Warns when there is no link; errors when no graph
    root is found.

                                                           *:LogseqToday*
:LogseqToday
    Open `journals/<date>.md` for today, where `<date>` follows
    |logseq-config| `journal_format` (default `%Y_%m_%d`).

                                                              *:LogseqNew*
:LogseqNew [title]
    Open `pages/<title>.md`. Prompts via |vim.ui.input| when no
    title is given; cancelling aborts quietly.

                                                          *:LogseqGraphs*
:LogseqGraphs
    Pick the active graph (see |logseq-multigraph|) via Telescope
    (|vim.ui.select| fallback). The `(auto)` entry clears the
    override; choosing persists the choice and notifies.

                                                           *:LogseqGraph*
:LogseqGraph [title]
    Explore one page's links in a scratch `filetype=logseq-graph`
    buffer: Linked + Backlinks sections (`2 hops` at depth 2). The
    center is `[title]`, else the current `pages/*` / `journals/*`
    buffer, else a prompt. `●` = the target file exists, `○` =
    dangling (opens lazily, nothing is written until content +
    `:w`). Buffer-local keys: `<CR>` / `gf` open the entry under the
     cursor, `q` closes, `r` refreshes, `1` / `2` set the depth, `T`
     toggles dangling entries. The index builds synchronously and
     refuses graphs over |logseq-config| `graph_max_files` with a
     warning. See |logseq-graphview|.

                                                           *:LogseqTodos*
:LogseqTodos
    List every `- TODO` task of the graph via Telescope
    (|vim.ui.select| fallback) and jump to the choice's line
    (`:edit +lnum path`). The picker title shows the graph name;
    an empty graph warns instead of opening a picker.
    See |logseq-todos|.

                                                        *:LogseqTodosView*
:LogseqTodosView
    Show the same task list grouped by file in a read-only
    `filetype=logseq-todos` scratch buffer. Buffer-local keys:
    `<CR>` jumps to the task under the cursor, `q` closes.
    Re-running reuses the single view buffer. See |logseq-todos|.

                                                       *:LogseqCycleTodo*
:LogseqCycleTodo
    Cycle the `- MARKER` on the cursor line to its next state per
    |logseq-config| `todo_cycles`. Works in any modifiable buffer
    (warns otherwise); warns and leaves the line alone when it is
    not a cyclable task. Silent on success. See |logseq-todos|.

                                                    *:LogseqSmartAction*
:LogseqSmartAction
    Follow the `[[link]]` / `#[[link]]` / `#tag` under the cursor,
    else cycle the `- MARKER` task on the cursor line, else move the
    cursor down one line (see |logseq-smartaction|).

                                                       *:LogseqNextLink*
:LogseqNextLink
    Jump to the start of the next link after the cursor (see
    |logseq-smartaction|).

                                                       *:LogseqPrevLink*
:LogseqPrevLink
    Jump to the start of the previous link before the cursor (see
    |logseq-smartaction|).

==============================================================================
6. MAPPINGS                                          *logseq-mappings*

Only `<Plug>(LogseqFollow)`, `<Plug>(LogseqCycleTodo)`,
`<Plug>(LogseqSmartAction)`, `<Plug>(LogseqNextLink)`, and
`<Plug>(LogseqPrevLink)` are provided; no key is bound globally.
Markdown buffers inside a graph additionally get buffer-local `<CR>`
(smart action) and `[o` / `]o` (link navigation) from the ftplugin —
each key guarded independently, so a map that already exists (yours
or otherwise) is never clobbered. Suggested opt-in binds (e.g.
scoped to graph buffers, or global at your discretion): >lua
    vim.keymap.set('n', 'gf', '<Plug>(LogseqFollow)')
    -- GUI/kitty only: most terminals send Ctrl+Enter as plain Enter.
    vim.keymap.set('n', '<C-CR>', '<Plug>(LogseqCycleTodo)')
<
To rebind a buffer-local key, remove it first
(`:nunmap <buffer> <CR>`) and map the `<Plug>` targets yourself;
pre-setting your own map also wins, since the ftplugin skips keys
that are already mapped.

==============================================================================
7. CONFIGURATION                                      *logseq-config*

All keys, with defaults: >lua
    {
      graph_path = nil,        -- absolute path (nil = auto-detect)
      pages_dir = 'pages',
      journals_dir = 'journals',
      journal_format = '%Y_%m_%d', -- os.date format for journal stems
      picker = 'telescope',    -- (vim.ui.select fallback is automatic)
      graphs_dirs = {},        -- parent dirs scanned for graphs
      graphs_depth = 2,        -- how deep to scan under each dir
      graph_depth = 1,         -- :LogseqGraph explorer depth (1 or 2)
      graph_max_files = 2000,  -- max files indexed synchronously
      todo_cycles = {          -- :LogseqCycleTodo marker rotation
        { 'TODO', 'DOING', 'DONE' },
        { 'LATER', 'NOW', 'DONE' },
        { 'IN-PROGRESS', 'DONE' },
        { 'WAIT', 'TODO' },
        { 'WAITING', 'TODO' },
        { 'CANCELLED', 'TODO' },
        { 'CANCELED', 'TODO' },
      },
    }
<
Set via `vim.g.logseq` or `require('logseq').setup(opts)`.
Unknown keys are not errors; they are reported by |:checkhealth|.
`todo_cycles` replaces the defaults wholesale (no per-index merge),
with the usual precedence: defaults < `vim.g.logseq` <
`setup(opts)`. Malformed chains (empty, non-string entries) are
skipped at cycle time and reported by |:checkhealth| (warn-only),
never hard errors. See |logseq-todos| for the rotation rules.

Root resolution order (see |logseq-multigraph|): explicit per-call
`opts.root`, then the current buffer's graph (a buffer inside a graph
always wins, even over the active override), then the active graph,
then `graph_path` (strict — a configured-but-missing path resolves to
nothing rather than guessing), then the working directory.

==============================================================================
8. HEALTH                                              *logseq-health*

:checkhealth logseq verifies: Neovim version, discovered graphs
(count + names; single-graph mode when `graphs_dirs` is unset), the
effective graph and the step that resolved it (`buffer:…` / `active:…` /
`graph_path` / `auto:…`), a warning when the stored active-graph entry
went stale, graph readability, `pages/` + `journals/` presence,
Telescope availability (warn-only), unknown config keys
(warn-only), and malformed `todo_cycles` chains (warn-only).

==============================================================================
9. SEMANTICS                                        *logseq-semantics*

Lazy (dangling-ref) opens: `:LogseqFollow`, `:LogseqToday`, and
`:LogseqNew` never create files. A missing target opens as an empty
buffer flagged internally; `:w` on a still-empty page is refused
with a warning ("not writing empty page"), and the file appears only
after you add content and write. This mirrors Logseq, which deletes
empty pages instead of keeping 0-byte files.

Page titles map to filenames verbatim (spaces and case preserved):
`Machine Learning` <-> `pages/Machine Learning.md`.
No `___`/legacy translation is applied: the reference graph sets no
`:file-name-format` and contains no namespace pages, so inventing one
would diverge from Logseq. Titles containing `/` are refused with a
warning instead of opening a buffer that could never round-trip
(namespaces are out of scope for v0.1, see |logseq-intro|).

10. MULTIPLE GRAPHS                               *logseq-multigraph*

Several file graphs are supported. Point |logseq-config| `graphs_dirs`
at parent directories and switch between the discovered graphs with
|:LogseqGraphs|. Opt-in: with `graphs_dirs` unset, behavior is exactly
single-graph v0.1. >lua
    vim.g.logseq = {
      graphs_dirs = { '~/dev', '~/notes' },
      graphs_depth = 2,
    }
<
Graphs are auto-discovered by scanning for `logseq/config.edn` or
`pages/` + `journals/` siblings. Hidden directories are skipped,
symlinks are not followed, and missing scan dirs scan as empty. The
scan runs on demand (picker open, |:checkhealth|) — never at startup,
so there is no cache to invalidate.

The picker lists `graph_path` plus every discovered graph as
`name — path`, and the `(auto)` entry clears the override back to
plain resolution. Choosing sets the active graph, persists it to
`stdpath('data')/logseq.nvim/active` so it survives restarts, and
notifies. With nothing to offer it warns and hints at `graphs_dirs`;
a stale `graph_path` stays listed and errors loudly on selection
rather than resolving elsewhere.

Root resolution order, first hit wins:
1. Explicit per-call `opts.root`.
2. The current buffer's graph — a buffer inside a graph always wins,
   even when `graph_path` is set or another graph is active.
3. The active graph, if still a valid root.
4. `graph_path`, strict: set-but-missing resolves to nothing (no
   silent fallback to the working directory).
5. Upward search from the working directory.

Scope follows the root: `:LogseqFind` lists only the current graph's
pages and journals, and `:LogseqToday` opens into its `journals/`.
Switching never `:cd`s and never touches other buffers.

==============================================================================
11. GRAPH EXPLORER                               *logseq-graphview*

`:LogseqGraph [title]` renders the M6.1 link index for one page — no
new dependencies, no async machinery: the index builds synchronously
over `pages/*.md` + `journals/*.md` and refuses graphs over
|logseq-config| `graph_max_files` (default 2000) with a warning
instead of stalling. Namespace targets (`[[a/b]]`) are skipped by the
index, matching the facade's out-of-scope refusal (see
|logseq-semantics|); self-loops list under Linked but never as their
   own backlink.

==============================================================================
12. TODO LISTS                                     *logseq-todos*

`:LogseqTodos` (picker) and `:LogseqTodosView` (scratch buffer) show
every `- <STATUS> text` task of the current graph — like Logseq
desktop's TODO query. Both share one scanner
(`graph.list_pages()` + per-file `readfile`); both are jump-only v1
(no status toggling) and read-only (nothing is ever written).

Markers are uppercase-only: `TODO`, `NOW`, `LATER`, `DOING`,
`IN-PROGRESS`, `WAIT`, `WAITING` sort first (file-then-line), then
`DONE`, `CANCELLED`, `CANCELED` last. Lowercase `todo` is plain
text, not a task. Bullets `-` and `*` are accepted; numbered lists
(`1.`) are rejected. Priorities (`[#A]`) and `SCHEDULED:` /
`DEADLINE:` stay plain text inside the task. Empty graphs warn
(`no tasks found under <root>`) instead of opening anything.

The picker shows `[STATUS] title: text` under a
`Logseq Todos — <graph>` title and jumps to `path:lnum` on choice.
The view groups the same tasks by file (`## title (kind)` sections
with `- [STATUS] lnum: text` rows; the `lnum` → `{path}` map lives
in `b:logseq_todos`). Buffer-local keys: `<CR>` jumps to the task
under the cursor, `q` closes; re-running reuses the single view
buffer. No new |logseq-config| keys; root resolution reuses the
standard order (buffer → active → `graph_path` → cwd).

CYCLING                                                       *logseq-cycle*

|:LogseqCycleTodo| rotates the `- MARKER` on the cursor line through
the |logseq-config| `todo_cycles` chains and writes it back in a
single undo step (cursor kept, silent on success). It works in any
modifiable buffer — not just graph files — and is the only
state-changing TODO operation (the picker and view stay jump-only).

Rotation rules: the marker advances to the next entry of the first
chain containing it; the last entry wraps to the first (so `DONE`
becomes `TODO` again — states are never stripped to bare text).
First chain wins: with the defaults, `LATER → NOW → DONE` rejoins
the main chain at `DONE`, and a further cycle yields `TODO`.
A marker in no chain warns (`no cyclable task`) and leaves the line
alone; non-task lines and non-modifiable buffers warn likewise.
Indent, bullet (`-`/`*`), and the task text are preserved
byte-for-byte. Example custom chains (wholesale replacement): >lua
    vim.g.logseq = { todo_cycles = { { 'TODO', 'DONE' } } } -- skip DOING
<
Multi-line cycling and timestamps/LOGBOOK are out of scope for v1.

==============================================================================
13. SMART ACTION                                 *logseq-smartaction*

`:LogseqSmartAction` (buffer-local `<CR>` in graph files) picks by
line, link-first:

1. A `[[link]]`, `#[[link]]`, or `#tag` under the cursor is followed
   (so a link inside a `- TODO` line follows the link; tags open
   their page directly, with no picker).
2. Else a `- MARKER` task line is cycled per |logseq-todos|.
3. Else the cursor moves down one line (a plain, mapping-immune
   `<CR>` motion, silent at the last line).

`:LogseqNextLink` / `:LogseqPrevLink` (buffer-local `]o` / `[o`)
jump to the start of the next / previous link. The comparison is
strict: a cursor sitting on a link moves on to the following one.
At the ends (or with no links at all) they are silent no-ops —
no wrap-around, no notifications.

Unlike obsidian.nvim's smart action there is no heading/fold
handling (`za`), no inlay-hint step, and no tag picker; headings
fall through to the move-down branch. The Lua mirrors are
`require('logseq').smart_action(opts)` (`{root=}` threads through
to the follow step) and `.nav_link('next' | 'prev')` (asserts on
any other direction).
